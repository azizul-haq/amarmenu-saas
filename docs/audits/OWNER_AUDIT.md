## 1. Feature Audit Matrix

Status Legend:
- **VERIFIED**: Proven functional with cited automated test name or direct database verification.
- **UI-ONLY**: Feature exists visually in frontend code but lacks backend database support/enforcement.
- **BACKEND-ONLY**: Functionality exists in database RPCs/triggers but has no frontend UI interface.
- **SIMULATED**: Feature behavior is mocked (e.g. browser dialog, synthetic timer, mock data).
- **PARTIAL**: Implemented only for specific execution paths (detailed in notes).
- **NOT BUILT**: Advertised or planned capability with neither UI nor backend implementation.
- **UNKNOWN**: Status indeterminate without running interactive live browser session.

## 2. Special Audit Sections

### A. Features Advertised in Docs / Plans But Not Built
1. **Plan Table Limit Enforcement (`max_tables`)**: `plans` defines `max_tables` (Starter: 15, Growth: null/unlimited, Enterprise: null/unlimited), but `createRestaurantTable` executes an unconstrained `INSERT INTO restaurant_tables`. (Confirmed unenforced in Chunk 22b).
2. **Bulk Menu Import**: Mentioned in onboarding plans as CSV/Excel upload; no UI button or backend parser exists.
3. **Restaurant Profile & Tax Rate Editing Form**: `RestaurantSettings.tsx` displays "Additional Settings (Coming Soon)" for contact info, VAT percentage, and service charge rate.
4. **Hourly Sales Breakdown**: Mentioned in reporting blueprints; only daily time-series is calculated.
5. **Split / Multi-Tender Counter Payments**: No support for splitting a single order across Cash + bKash.
6. **Direct Image Upload to Storage**: Menu items require an external image URL string; no file picker or bucket upload exists.
7. **Opening / Operating Hours Configuration**: Listed in settings roadmap; column does not exist in `restaurants` table.

### B. Features That Exist Only in UI (No Database Enforcement)
1. **Forced Password Change on First Login (`must_change_password`)**: Handled entirely in the React app (`ForceChangePasswordModal.tsx`); the PostgreSQL database does not reject operational RPCs if an account still has `must_change_password: true` in its auth metadata.
2. **Thermal Printer Status**: The UI shows print buttons and records print counts, but has no actual hardware communication with physical ESC/POS thermal printers.
